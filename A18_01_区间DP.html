18.1　区间 DP

状态不再是"第几个数"，而是"一整段区间"——枚举一个分割点，把区间拆成两半分别求解，再合并起来。

① 什么是区间 DP

13 模块讲过的线性 DP，状态通常是"到第 i 个位置为止"；区间 DP 的状态则是一整段区间 [l, r]，常见于"把一段序列不断合并/分割，求最优代价"这类问题——比如把一排石子堆不断合并成一堆、把一个字符串通过插入字符变成回文串、给一串矩阵加括号求最少乘法次数。这类问题的共同点是：一段区间的最优解，可以通过枚举一个分割点，拆成两个更小的子区间分别求解，再合并起来。

② 核心思想：枚举分割点，合并两个子区间

设 dp[l][r] 表示区间 [l, r] 的最优解。枚举一个分割点 k（l ≤ k < r），把 [l,r] 拆成 [l,k] 和 [k+1,r] 两段，这两段各自的最优解是 dp[l][k] 和 dp[k+1][r]（已经算好），再加上"合并这两段"本身需要付出的代价，取所有分割点里最优的一种：

要素区间 DP 里对应什么
状态定义dp[l][r]：区间 [l,r] 的最优解（具体含义因题目而异）
转移方程dp[l][r] = min{ dp[l][k] + dp[k+1][r] + cost(l,r) }，枚举 k∈[l,r-1]
初始化dp[i][i] = 0（区间只有一个元素，不需要合并，没有代价）
填表顺序按区间长度从小到大——先算长度为 2 的区间，再算长度为 3 的……（见 ⑥ 陷阱）

④ 完整代码
C++ · 石子合并（区间 DP）
1int a[MAXN], prefix[MAXN], dp[MAXN][MAXN], n;
2
3int Sum(int l, int r) { return prefix[r] - prefix[l-1]; }
4
5int IntervalDP()
6{
7 for (int i = 1; i <= n; i++) prefix[i] = prefix[i-1] + a[i];
8 // dp[i][i] = 0 全局数组默认已经是 0，不需要手动初始化
9
10 for (int len = 2; len <= n; len++) // ★ 按区间长度从小到大枚举
11 {
12 for (int l = 1; l + len - 1 <= n; l++)
13 {
14 int r = l + len - 1; // 由左端点 l 和长度 len 推出右端点 r
15 dp[l][r] = 1e9;
16 for (int k = l; k < r; k++) // 枚举分割点
17 dp[l][r] = min(dp[l][r], dp[l][k] + dp[k+1][r] + Sum(l, r));
18 }
19 }
20 return dp[1][n];
21}
💡
三层循环，缺一不可：最外层 len 决定"先算短区间、再算长区间"这个填表顺序；中间层 l 枚举这个长度下所有可能的起点（r 由 l+len-1 直接算出，不需要单独循环）；最内层 k 枚举分割点。dp[l][k] 和 dp[k+1][r] 的区间长度都严格小于 len，按外层循环的顺序，这两个值必然已经算好。
⑤ 复杂度分析

状态数是 O(n²)（l、r 各 n 种取值），每个状态转移要枚举分割点 k，O(n)。整体时间复杂度 O(n³)——比线性 DP 慢一个数量级，n 通常不会太大（几百到一千出头比较常见）。

⑥ 常见陷阱
⚠
填表顺序写反，直接按 l、r 从小到大双重循环：这是区间 DP 最容易犯的错误——如果直接写 for(l=1;l<=n;l++) for(r=l;r<=n;r++)，在算 dp[1][4] 时可能 dp[2][4] 还没被算过（因为 r 的内层循环还没跑到需要的组合），导致用到了未初始化的脏数据。正确做法是按区间长度 len 从小到大作为最外层循环，确保用到的子区间一定是"更短的、已经算好的"。
⚠
忘记预处理前缀和，每次现算 cost(l,r)：如果 cost(l,r) 本身需要 O(n) 现场累加（而不是像本节这样用前缀和 O(1) 查询），整体复杂度会从 O(n³) 恶化成 O(n⁴)，在数据规模稍大时就会超时。
⚠
dp 初始值设置不当：第 15 行 dp[l][r] = 1e9 是求最小值时的"正无穷"占位，如果题目求的是最大值，要改成一个足够小的负数；如果忘记初始化、或者初始化成 0，min／max 比较时会被这个错误的初始值污染，导致结果不正确。
